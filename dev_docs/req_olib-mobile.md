## 背景

olib-mobile 新增了「电脑联动」页（首页快捷功能进入，分支 `feat/desktop-link-hub`）：

- 手机扫码配对一次后**记住这台电脑**（保存 `http://IP:8765`），之后打开页面先调 `GET /api/info`
  免认证探测，在线就直接取书 / 发书，不再扫码。
- 支持从手机已下载列表**多选批量发书**（逐本 `POST /api/upload`）。
- 下载页、书架导入、书单分享里原有的「发送到电脑 / 从电脑导入」也都改为优先用记住的电脑。

手机端只用了现有接口（`/api/info`、`/api/files`、`/download/{filename}`、`/api/upload`、`/api/booklist`），
**不改桌面端也能工作**。但桌面端有两处体验缺口，让「配对一次、之后免操作」打了折扣。

## 需求 1（推荐）：记住无线传书开关，启动时自动开启

### 现状

- 无线传书只能在书架页点「无线传书」→ 弹窗里手动开启（`WirelessTransfer.tsx` → `start_lan_server`）。
- 电脑端每次重启后服务都是关闭的。

### 问题

手机已经记住了电脑，但只要用户忘了在电脑上点开无线传书，手机「电脑联动」页就显示「暂时连不上电脑」，
用户得回到电脑前操作。记住配对的价值被这一步抵消了。

### 期望

- 配置新增一项，如 `lan_auto_start: bool`（默认 `false`，不改变现有用户行为）。
- 用户在电脑上**手动开启**无线传书时记为 `true`，**手动关闭**时记为 `false`。也就是「上次是开着的，下次启动就自动开」，不需要额外的设置项。
  如果你们更倾向于做成设置页里的显式开关，也可以。
- 应用启动时，若 `lan_auto_start == true`，按上次的端口（默认 8765）后台启动服务；
  启动失败（例如端口被占用）只记日志并保持关闭，不弹窗打扰用户。
- 书架页「无线传书」按钮的「传书中」状态，要能反映自动开启的情况（现在 `BookshelfPage` 用 `getLanStatus()` 读状态，应该已经满足，请顺带确认一下）。

### 注意

- 端口尽量保持稳定：手机记住的是 `IP:端口`，端口一变，手机就要重新扫码。
- 安全面不变：服务本来就监听 `0.0.0.0`、无认证（见 `lan-server.md`）。自动开启只是让这个状态持续得更久。
  如果担心公共 Wi-Fi 场景，可以在开启时提示一次「仅在可信网络使用」，具体由你们决定。

## 需求 2：收到手机发来的书 / 书单时，在电脑上提示

### 现状

- `receive_upload` 落盘后只有 `log::info!("📥 LAN upload received: ...")`，界面没有任何反馈。
- `/api/booklist` 导入后同样只有日志。

### 问题

手机端一次能批量发好几本书，但电脑上看不出书到了没有、放在哪里，用户只能去文件夹里翻。

### 期望

- 上传成功后向前端 emit 一个事件（如 `lan://file-received`，payload `{ name, size }`）；
  书单导入后 emit `lan://booklist-received`（payload `{ imported, skipped }`）。
- 前端收到后：
  - 弹一个轻提示（toast），例如「收到来自手机的《xxx》」。批量连续到达时合并成「收到 3 本书」，避免连续刷屏。
  - 如果当前在书架页，刷新列表，让新书立刻出现。
  - 可选：提示里带「打开所在文件夹」。
- 应用最小化或在后台时，可以考虑走系统通知。不是必须的。

### 待桌面端确认

- 上传的文件落在 `download_folder` 后，**书架页是否会显示它**？书架如果是基于数据库记录、而不是扫描目录，
  那手机发来的书可能不会出现在书架上，这个需要你们确认，必要时补上入库逻辑。

## 不需要改的

- 接口契约不变，手机端不依赖上面两项中的任何一项，两边可以分别发版。
- 无需恢复 token 认证。手机端保留了 token 字段和 401 处理，日后恢复认证时只改桌面端即可。
